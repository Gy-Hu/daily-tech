五个值得关注的方向

按相关性、技术深度、新鲜度、影响与讨论质量排序

01

验证对象从“最终答案”扩展到状态与数据路径

RTL coverage、编译器 cache、Agent 计划与 PR 证据都可能在表面通过时仍然错误；今天多项工作都用独立状态对照或外置 oracle 补洞。

02

可检查证书继续压缩求解器信任边界

紧凑 SAT 编码不只追求更快，还为 UNSAT 下界给出 DRAT 证书；HyperRecHML 则把高表达力超逻辑拉回可判定模型检测。

03

FPGA 优化回到编译器与 ISA 共设计

FINN 多阈值 lowering、应用专用 RISC-V 指令编码、Krylov DSL 到可编程数据通路，均把“加速器”做成可生成、可度量的编译问题。

04

Agent 基础设施从提示词转向隔离与预算

SPACE 用 microVM 管生命周期，ToolBottleneckBench 固定 harness 预算，HPCAgent-Bench 用隐藏 fuzz oracle；性能数字开始附带资源边界。

05

本地与开放模型进入“能否承载”的阶段

501B/23B-active Beam 提供开放权重和 1M context，但 NVFP4 仍约 280GB；模型开放不等于个人工作站可部署，内存拓扑必须单列。

今天可采取的 3 个行动

优先选能转化成实验或设计检查表的内容

精读：RTL coverage closure 的独立数据 oracle

把论文的三层证据拆成 reachability、scoreboard、end-to-end monitor，检查其 FIFO 漏接环节；对照现有 FermatVerification-RTL 工作流列出“覆盖到但数据错”的最小反例。

复现：Rondo 的 state reset 三路差分

在一个含缓存的编译/综合工具上构造 A→B 调用序列，对比 fresh process、reset state 与 retained state；优先记录可最小化的序列与 cache key。
